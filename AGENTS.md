# Правила проекта

## Файлы и инструкции

- [README.md](README.md) — подробный процесс, настройка среды Linux/macOS, команды и примеры имён файлов. Этот файл — краткая рабочая памятка для агента.
- [transcript-proofread](.agents/skills/transcript-proofread/SKILL.md) — правила корректуры и работы с неясными местами.
- [conspect](.agents/skills/conspect/SKILL.md) — три волны подготовки материала: читаемая транскрипция → ход развития мысли → итоговый конспект.
- Результаты встреч сохранять в `output/<название встречи>/`. Исходники сохранять неизменными, предыдущие утверждённые редакции — в `архив/` этой встречи.

## Транскрипция и команды

- Для транскрипции использовать AssemblyAI через существующий скрипт `main.py`.
- Запуск из корня проекта: `.venv/bin/python main.py "ПУТЬ_К_ВИДЕО"`. Скрипт принимает один позиционный аргумент — путь к файлу. Флаг `--help` не поддерживается; строка использования: `Usage: python main.py VIDEO_FILE`.
- Перед запуском обеспечить наличие переменной окружения `ASSEMBLYAI_API_KEY`. Скрипт не загружает `.env` автоматически. Не выводить ключ в логи или ответы.
- Скрипт использует EU endpoint AssemblyAI, автоматическое определение языка и разделение по говорящим. Сохраняет `<имя>.json` с транскрипцией и `<имя>.speakers.json` с полями `person_id`, `name`, `role` рядом с переданным файлом.
- Чтобы результаты попадали в `output/`, перед запуском разместить копию или символическую ссылку на исходный файл в `output/<название записи>/` и передать этот путь в `main.py`. Для результатов `input.json` и `input.speakers.json` назвать копию или ссылку `input` с расширением исходного файла. Имена говорящих заполнять по записи, не переносить метки говорящих из других транскрипций без проверки.
- Диалог для чтения и сверки: `.venv/bin/python create_dialogue.py "output/<название встречи>/input.json" -o "output/<название встречи>/dialogue.md"`. Конвертер выводит ID реплики и начало/конец с точностью до миллисекунды: `[U000001 | 00:00:00.000–00:00:01.234] A:Имя: текст`. ID относится к позиции в конкретном исходном JSON; сохранять его при дальнейшей редактуре и не переносить между разными распознаваниями. Исходный JSON сохранять.

## Краткий workflow

1. **Собрать источники.** Сохранить запись, Zoom-транскрипцию с таймкодами и результат AssemblyAI. Если одного источника нет, указать это; уже готовые результаты использовать повторно.
2. **Сверить и вычитать.** Сопоставить шкалы времени и полноту по содержанию. Сначала собрать `01 — Транскрипция на проверку.md` по обоим источникам и сохранить копию до корректуры, затем применить `transcript-proofread`. Объединение проверять по покрытию обоих источников, корректуру — по сохранности реплик, ID и таймкодов относительно собранного текста. Существенные сомнения отметить diff с номером вопроса, таймкодом и контекстом. Указать легенду: `−` — Zoom/первый источник, `+` — AssemblyAI/второй; знаки не означают подтверждённую замену.
3. **Получить уточнения и утвердить транскрипцию.** Человек проверяет спорные места по записи. Ответы и основания фиксировать в `02 — Проверка спорных мест.md`, итог — в `03 — Полная транскрипция.md`. Не угадывать смысл; неустановленные места помечать и не использовать как факты. Сохранять авторство, порядок реплик и проверенные таймкоды.
4. **Показать ход мысли.** По полной транскрипции с помощью `conspect` создать `04 — Ход развития мысли.md`: постановка вопросов, на что обращали внимание, уточнения и формулирование идей. Уже выверенную транскрипцию повторно очищать не требуется.
5. **Составить итоговый конспект.** На основе хода мысли, с проверкой по транскрипции, создать отдельный файл `<название встречи> - конспект.md`. Простым языком раскрыть идеи, понятия, правила с условиями, ключевые вопросы и практику, если она прозвучала. Сохранять рассуждения, раскрывающие понятия и связи между ними; убирать отступления и повторы без нового смысла. Краткость — следствие этой работы, а не самостоятельная цель. «Лекция» — стиль связного объяснения; значимые образы, метафоры и телесные ощущения сохранять с контекстом, без придуманного толкования.
6. **Проверить и завершить.** Сверить существенные положения с источником, сохранить ориентиры на реплики и обозначить оставшиеся неясности. Дать ссылки на результаты. Публикация — при необходимости по запросу пользователя; отдельный файл «Материал для публикации» по умолчанию не нужен.

## Как поддерживать согласованность

- При изменении процесса, имён результатов или команд обновлять затронутые места в `AGENTS.md`, `README.md` и соответствующем `SKILL.md`; при изменении назначения навыка — также его `agents/openai.yaml`. Не копировать подробную инструкцию сюда: оставлять краткое правило и ссылку.
- Команды и технические ограничения сверять с текущими `main.py`, `create_dialogue.py` и используемыми скриптами. Настройку среды и версии зависимостей описывать в `README.md`.
- Смысловые исправления вносить сначала в утверждённую транскрипцию и журнал встречи, затем обновлять ход развития мысли, итоговый конспект и опубликованную версию, если она есть. Поздний конспект не использовать для восстановления исходной речи.
