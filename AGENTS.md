# Рабочий процесс и правила проекта

## Назначение документов

[README.md](README.md) знакомит человека с целью, инструментами и структурой проекта. [INSTALL.md](INSTALL.md) содержит установку среды, настройку API-ключа и Zoom. Здесь описан рабочий процесс; требования к корректуре и содержанию документов находятся в навыках [transcript-proofread](.agents/skills/transcript-proofread/SKILL.md) и [conspect](.agents/skills/conspect/SKILL.md).

Читай инструкции по текущему этапу. Для смысловой работы используй актуальный Markdown, а не полный JSON с данными каждого слова. JSON сохраняй и обрабатывай программно, извлекая только нужные сведения. После начала корректуры не заменяй рабочий Markdown повторной генерацией из исходного JSON.

## 1. Подготовить встречу и источники

- Создай `output/<название встречи>/`; сохрани неизменные исходники и предыдущие утверждённые редакции в `архив/` этой встречи.
- Определи название, дату, известных участников и задачу читателя. Укажи доступность записи, её продолжительность, обрезки и границы материала.
- Сохрани Zoom-транскрипцию с таймкодами и результат AssemblyAI. Уже готовые результаты используй повторно. Если одного источника нет, обозначь это; можно работать с одной транскрипцией и записью. При недоступной записи укажи пределы текстовой проверки.
- Перед новым распознаванием проверь среду по INSTALL.md. `ASSEMBLYAI_API_KEY` должен быть экспортирован в том же терминале; `.env` не загружается автоматически. Ключ не выводить в ответы или логи.

### Выбрать файл для распознавания

Если готовый аудиофайл уже есть, используй его напрямую: извлечение через FFmpeg не требуется. Размести копию или символическую ссылку в папке встречи с именем `input` и исходным расширением. Команды выполняются из корня проекта; пример для M4A:

```bash
mkdir -p "output/Название встречи"
cp "/путь/к/записи.m4a" "output/Название встречи/input.m4a"
.venv/bin/python main.py "output/Название встречи/input.m4a"
```

Если есть только видео, сначала извлеки звуковую дорожку локально:

```bash
.venv/bin/python extract_audio.py "/путь/к/записи.mp4" --output-dir "output/Название встречи"
```

Затем передай в `main.py` **созданный аудиофайл**. Для MP4 с дорожкой AAC результат — `input.m4a`:

```bash
.venv/bin/python main.py "output/Название встречи/input.m4a"
```

Расширение зависит от кодека: скрипт сообщает точный выходной путь. Он копирует дорожку без повторного сжатия, изменения частоты или числа каналов и не перезаписывает существующие результаты. Без `--output-dir` использует `output/<имя видео без расширения>/`. Исходное видео сохрани для сверки и возможной работы с изображением; обрезать паузы или менять скорость перед распознаванием не нужно.

Рядом создаётся `input.audio-source.json`: путь к исходному видео, выбранная дорожка, кодек и исходные начальные метки времени. Это служебное описание, на распознавание отправляется только аудиофайл. При переносе дорожки в другой контейнер начало шкалы времени может измениться; проверь соответствие аудио и видео по началу, середине и концу, а смещение запиши в журнал. Ненулевое исходное смещение скрипт дополнительно выводит как предупреждение.

Если аудиодорожек несколько, скрипт требует явного выбора. `--audio-stream 0` выбирает первую среди аудиодорожек, `1` — вторую и т. д.; это не общий индекс потока в видео. Сначала проверь, какая содержит нужную речь. Если голоса участников распределены между дорожками, выбор одной не заменяет сборку общего звука — такой материал требует отдельной подготовки.

Если дорожка или её контейнер не поддерживаются извлечением без перекодирования, не меняй кодек вслепую: разберись с форматом отдельно. AssemblyAI также принимает исходное видео напрямую; это допустимый запасной путь после проверки лимитов загрузки. Извлечение аудио уменьшает загрузку, а не стоимость распознавания той же длительности. [Аудио и видео тарифицируются одинаково](https://www.assemblyai.com/docs/faq/does-it-cost-more-to-transcribe-an-audio-or-video).

### Получить транскрипцию

`main.py` принимает только путь к записи, без флага `--help`. Использует EU endpoint AssemblyAI, автоматическое определение языка и разделение по говорящим. Рядом сохраняются `input.json`, `input.speakers.json` и автоматически созданный `input.dialogue.md`. В терминале — только статус, язык, число реплик и пути.

Имена и роли в `input.speakers.json` заполняй по записи. Метки говорящих разных источников не сопоставляй автоматически. Для существующего JSON или обновлённых имён до начала корректуры:

```bash
.venv/bin/python create_dialogue.py "output/Название встречи/input.json"
```

Формат диалога: `[U000001 | 00:00:00.000–00:00:01.234] A:Имя: текст`. `--short` убирает только метку `A`, сохраняя имя, ID и время. Отсутствующее время обозначается `??:??:??.???`; его нельзя угадывать. ID относится к позиции в конкретном JSON и сохраняется при редактуре. При объединении независимых распознаваний указывай источник, например `AssemblyAI:U000001`.

При ошибке конвертации JSON и файл говорящих остаются сохранёнными: исправь причину и запусти только `create_dialogue.py`, не повторяя облачное распознавание. Перед повторным запуском с теми же именами архивируй предыдущие результаты.

## 2. Сверить источники и выполнить корректуру

1. Прочитай оба текста целиком. Сопоставь одинаковые фразы в начале, середине и конце; за основу времени возьми сохранённую запись. Зафиксируй смещение шкал. При обрезках и паузах проверяй соответствие по участкам.
2. Выбери основной текст по качеству и полноте. Собери `01 — Транскрипция на проверку.md`, сохранив уникальные фрагменты обоих источников, авторство, порядок и происхождение вставок.
3. Проверь объединение по покрытию обоих источников, говорящим и шкалам времени. Сохрани копию собранного текста до корректуры в `архив/` — это база последующего сравнения. Разное число реплик у разных сервисов допустимо.
4. Примени `transcript-proofread`: исправь однозначные ошибки, сохрани подтверждённые человеком формулировки и существенные неясности. После корректуры проверь сохранность реплик, ID и таймкодов относительно собранного текста; подтверждённые изменения времени или авторства запиши в журнал.

Особенно проверяй отрицания, термины, числа, условия, причинные связи и роли участников. Совпадение двух распознаваний не доказывает точность: сомнительное общее чтение тоже требует проверки. Различия пунктуации и разбивки без изменения смысла не должны перегружать список вопросов.

В рабочем тексте спорные варианты оформляй рядом с номером вопроса, таймкодом/ID, автором и достаточным контекстом:

```diff
- Zoom: Это нужно делать, если условие не выполнено.
+ AssemblyAI: Это не нужно делать, если условие не выполнено.
```

Это условный пример. Легенда обязательна: `−` — Zoom/первый источник, `+` — AssemblyAI/второй. Знаки обозначают варианты, а не подтверждённую замену. Один вопрос должен уточнять одно существенное сомнение. Если повреждены оба варианта, отметь это.

В `02 — Проверка спорных мест.md` веди номера, ориентиры, вопросы, ответы, основания и статусы. Diff достаточно хранить в рабочем тексте. Пустой список вопросов создавать не нужно.

## 3. Внести уточнения и утвердить транскрипцию

Человек прослушивает спорный участок вместе с контекстом. Фиксируй ответ и основание: прослушивание записи, подтверждение говорящего или память; ответ по памяти не выдавай за аудиопроверку. Статусы: решено / частично уточнено / не удалось разобрать. Если восстановить речь нельзя, сохрани понятную часть и отметку `[неразборчиво]`.

После первичного полного чтения вноси локальные ответы адресно, по текущему Markdown:

```bash
.venv/bin/python read_dialogue.py "output/Название встречи/01 — Транскрипция на проверку.md" U000007 --context 2
```

Можно указать несколько ID, включая `AssemblyAI:U000007`. Скрипт сохраняет вступление и выбранные блоки, объединяет пересечения и обозначает пропуски. Выборку нельзя записывать поверх полного текста. Если ID отсутствует или дублируется, скрипт завершится с ошибкой; в старых файлах используй поиск по времени или точной фразе.

Две соседние реплики — начальный контекст. Проверяй связанные употребления понятий; при влиянии уточнения на другие части расширяй проверку. Если первичное чтение не выполнено, контекст утрачен или источник существенно изменился, восстанови необходимое понимание, при необходимости прочитав всё. Не выполняй массовую замену по одному ответу. После правки сверь разницу, сохрани ID и время, обнови статус вопроса.

Создай `03 — Полная транскрипция.md`. Сохрани реплики, примеры и содержательные повторы: сокращение относится к следующей волне. В начале укажи источники, статус, дату редакции, шкалу времени и границы проверки. Не утверждай полную аудиопроверку, если запись целиком не прослушивалась.

Транскрипция готова, когда учтены начало, основные части и конец, известные пропуски обозначены, существенные сомнения разрешены либо явно признаны неустановленными, а невыбранных diff-вариантов нет. Неясность центрального тезиса или шага практики требует проверки либо явного ограничения; её нельзя закрывать догадкой.

## 4. Подготовить ход развития мысли и итоговый конспект

Примени `conspect` к полной утверждённой транскрипции, указав задачу читателя. Навык создаёт два документа в папке встречи:

- `04 — Ход развития мысли.md` — постановка вопросов, на что обращали внимание, уточнения и формулирование идей в последовательности беседы;
- `<название встречи> - конспект.md` — связное объяснение основных идей, понятий, правил с условиями, ключевых вопросов и имеющейся практики. Подставь название, сохранив разделитель ` - `.

Три волны: подготовленная транскрипция → ход мысли → итоговый конспект. Уже выверенную транскрипцию повторно очищать не нужно. При первом составлении конспекта прочитай источник целиком; документ о ходе мысли не заменяет его. Для длинного материала читай последовательными частями без пропусков, затем проверяй связи между частями.

Сохраняй рассуждения, раскрывающие ключевые понятия и связывающие их между собой; убирай отступления и повторы без нового смысла. Краткость — следствие аккуратной работы, а не самостоятельная цель. «Лекция» обозначает стиль ясного последовательного объяснения. Значимые образы, метафоры и телесные ощущения сохраняй с контекстом и авторством, без придуманного толкования.

Различай практику автора, пример и редакторское упражнение. Не превращай пример в обязательное задание, не дописывай шаги, условия, число повторений или ответы. Новые упражнения допустимы только по отдельному запросу с явным обозначением редакторского авторства.

## 5. Проверить результат и завершить

- Основные идеи, понятия, правила, ключевые вопросы и объясняющие их рассуждения отражены; оговорки, отрицания, ограничения и разногласия сохранены.
- Существенные положения имеют автора и проверяемый ориентир в источнике: таймкод, ID или другой доступный указатель.
- Практика соответствует записи; значимые образы и телесные ориентиры не потеряны и не получили нового смысла.
- В итоговом тексте нет невыбранных diff-вариантов и служебных заметок; ограничения источника понятны читателю. Редакционное изложение не выдаётся за дословную речь.

Дорабатывай `<название встречи> - конспект.md` под задачу, сохраняя прежнюю утверждённую редакцию в архиве. Дополнительный файл «Материал для публикации» не нужен. Дай ссылки на результаты и укажи существенные оставшиеся неясности. Публикация выполняется при необходимости по запросу пользователя; после переноса проверь оформление и ссылки, сохрани дату и адрес публикации в журнале.

## Файлы встречи

```text
output/<название встречи>/
├── input.m4a                        # готовое аудио или дорожка из видео; расширение зависит от кодека
├── input.audio-source.json          # только если аудио извлечено скриптом
├── zoom.vtt
├── input.json
├── input.speakers.json
├── input.dialogue.md
├── 01 — Транскрипция на проверку.md
├── 02 — Проверка спорных мест.md      # если есть вопросы
├── 03 — Полная транскрипция.md
├── 04 — Ход развития мысли.md
├── <название встречи> - конспект.md
├── Журнал.md
└── архив/
```

Для старых встреч сохраняй существующие имена, если переименование не запрошено. Смысловые исправления сначала вноси в утверждённую транскрипцию и журнал, затем обновляй ход мысли, конспект и опубликованную версию, если она есть. Поздний конспект не используй для восстановления исходной речи.

## Дополнительная обработка чата

Если нужна очистка выгрузки от `MessageActionChatJoinedByLink`, запускай скрипт на копии: он меняет переданный файл на месте.

```bash
mkdir -p "output/Название встречи"
cp "/путь/к/messages.md" "output/Название встречи/messages-clean.md"
bash scripts/remove-chat-joined-by-link.sh "output/Название встречи/messages-clean.md"
```
